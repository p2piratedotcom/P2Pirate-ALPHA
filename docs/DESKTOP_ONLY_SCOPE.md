# Desktop-only scope and platform cleanup

P2Pirate's intended app targets are Linux, macOS and Windows. Linux is the
locally built target. macOS and Windows need native-host builds and runtime
checks before they can be described as supported releases. This document
records how to remove Web, Android and iOS app targets without removing Dart
code used by desktop builds.

## What can be removed

The root `web/`, `android/` and `ios/` directories contain Flutter app runners,
platform assets and metadata. None is needed to compile a Linux, macOS or
Windows runner. Once platform-specific references below are cleaned up, these
directories can be deleted in a dedicated change. The corresponding Web and
mobile CI workflows, deployment scripts and release instructions can then be
retired. Keep the upstream Git history and license notices intact.

## Couplings to resolve first

- `pubspec.yaml` points `flutter_launcher_icons.image_path` into `android/`.
  Remove the mobile icon-generator configuration or move its input before
  deleting that directory.
- `pubspec.yaml` includes `assets/packages/flutter_inappwebview_web/assets/web/`.
  This is a package asset, not a file in root `web/`; verify that desktop
  WebView use still works before removing any WebView dependency or asset.
- `lib/` and the SDK use conditional Web imports and mobile platform branches.
  Keep these during the runner cleanup. Removing them is a separate code
  refactor that needs desktop compile and wallet-flow checks.
- `.github/workflows/`, `.github/actions/`, deployment roles, `INSTALL.md`,
  `docs/` and `test_integration/` contain Web or Android build paths. Retire
  or update them in the same change as the runners, or CI and instructions
  will continue to target deleted platforms.
- `.metadata` records the platforms generated by Flutter. Update it with the
  platform cleanup, and avoid running unrestricted `flutter create .`, which
  could recreate runners. Flutter's desktop guide uses
  [`flutter create --platforms=windows,macos,linux .`](https://docs.flutter.dev/platform-integration/desktop)
  when desktop files need to be generated.

## Safe sequence

1. Disable the Web/mobile build and deploy jobs and update the documented
   support matrix. Keep the current desktop jobs.
2. Remove Web, Android and iOS runner-only configuration and their root
   directories; clean the mobile icon-generator entry and stale asset paths.
3. Resolve dependencies without changing the lockfile unintentionally, then
   analyze the changed Dart files and build Linux. Build macOS and Windows on
   their own hosts before publishing binaries.
4. Only then consider pruning Web/mobile-only Dart code or packages. Plugin
   implementations may be selected by Flutter for desktop, so deletion needs
   evidence from the resolved dependency graph and native builds.

Deleting the root runners alone is low risk to Linux code compilation, but it
would leave broken Web/Android CI and an Android icon path in this repository.
For that reason, the runner deletion is deferred to its own reviewable change.
Disabling Web/Android devices with `flutter config` affects a developer's
local Flutter installation; it does not change the repository or release
targets.
